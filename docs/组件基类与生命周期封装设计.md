# 组件基类与生命周期封装设计

> 状态：已定案
> 日期：2026-07-23
> 对应内核文档：`nervud-内核与系统服务架构决策.md` §7（App/Service 组件模型）、
> `nervud/internal/pkgregistry/manifest.go`（Package/Component 数据结构）

## 目标

消除 SDK 当前裸暴露 IPC 细节的问题。当前 `NervusClient`/`NervusServiceHost` 要求开发者手动管理 connect、handshake、endpoint 注册/解析、dispatch 路由——这些都是 OS 层的重复样板，不应出现在应用代码中。

新的组件基类层让开发者只需关注业务逻辑：声明 Component 类型、声明 Interfaces、实现对应方法。

## 架构

```
┌──────────────────────────────────────────────────────────┐
│                   用户应用代码                              │
│  class AudioApp : NervusApp()                             │
│  class AudioSvc : NervusService()                         │
├──────────────────────────────────────────────────────────┤
│               SDK 组件基类层（本方案）                      │
│  Component (abstract) → NervusApp / NervusService          │
├──────────────────────────────────────────────────────────┤
│            SDK IPC 层（已有，不对外暴露概念）                │
│  NervusClient / NervusServiceHost / Envelope / UDS        │
├──────────────────────────────────────────────────────────┤
│                    nervud                                  │
└──────────────────────────────────────────────────────────┘
```

上下层调用关系：组件基类层调用 IPC 层，IPC 层通过 UDS 与 nervud 通信。应用代码只感知组件基类层。

## Component 基类（abstract）

### 职责

Component 是所有 Nervus 组件类型的公共基类。它封装了所有与 nervud 建立连接和维持连接的样板：

1. 连接 `/run/nervus/nervud.sock`
2. Hello / HelloAck 协议握手
3. 连接状态维护与自动重连（带退避）
4. `onReady()` / `onStop()` 生命周期回调
5. `supervisorScope` + `Dispatchers.IO` 协程上下文

Component 不区分 consumer 还是 provider——这个区分由两个派生类完成。

### Kotlin API

```kotlin
abstract class Component(
    protected val config: ComponentConfig = ComponentConfig()
) : AutoCloseable {
    // ---- 生命周期（子类覆写） ----

    /** 连接就绪、握手完成、endpoint 已注册/已解析后调用 */
    protected open fun onReady() {}

    /** 组件正在停止；子类在此释放资源 */
    protected open fun onStop() {}

    // ---- 公共方法 ----

    /** 启动组件：连接 nervud 并注册/解析 endpoint */
    fun start()

    /** 关闭组件：断开连接、清理资源 */
    override fun close()

    /** 当前连接状态 */
    val state: ConnectionState  // DISCONNECTED / CONNECTING / CONNECTED / CLOSED
}

class ComponentConfig(
    val socketPath: String = "/run/nervus/nervud.sock",
    val sdkName: String = "nervus-app-sdk",
    val sdkVersion: String = "0.1.0",
    val handshakeTimeoutMs: Long = 5000,
    val autoReconnect: Boolean = true,
    val maxReconnectAttempts: Int = 5,
    val componentId: String = "", // 仅允许 [a-z][a-z0-9_]*，不可含连字符
)
```

### 内部行为（不在 API 中暴露）

```
start()
  ├─ connect UDS
  ├─ negotiate Hello/HelloAck  ← 内部调用 NervusClient/NervusServiceHost
  ├─ onConnect()               ← 子类在此注册/解析 endpoint
  ├─ launch reader loop        ← 读 Envelope 并分发
  ├─ launch ping loop          ← 保活
  └─ onReady()                 ← 通知子类准备完毕

close()
  ├─ onStop()
  ├─ unregister endpoints (Service) / 取消订阅 (App)
  ├─ disconnect UDS
  └─ cancel scope
```

start/close 的时序是固定的，子类不覆写这两个方法。

## NervusApp : Component（consumer 侧）

对应 manifest 中 `type: app` 的组件。它只消费（调用）其他服务提供的 Interface，不提供自己的 endpoint。

### Kotlin API

```kotlin
abstract class NervusApp(config: ComponentConfig = ComponentConfig()) : Component(config) {

    /** 声明本 App 需要消费的 Interface */
    protected abstract val requiredInterfaces: List<InterfaceRequirement>

    /**
     * 获取一个已解析的 Interface 的调用代理。
     * 在 onReady() 之后调用。
     */
    protected fun <T : Any> use(interfaceClass: KClass<T>): T
}

/** 一个 Interface 消费声明 */
data class InterfaceRequirement(
    val id: String,
    val minMajor: Int = 1,
    val maxMajor: Int = 1,
    val resourceType: String = "",
    val resourceRole: String = "",
    val isRequired: Boolean = true,
)
```

### 使用示例

```kotlin
class ControlConsoleApp : NervusApp() {
    override val requiredInterfaces = listOf(
        InterfaceRequirement("nervus.interface.audio.classifier", 1),
        InterfaceRequirement("nervus.interface.motion.base", 1),
    )

    override fun onReady() {
        // use<>() 返回动态代理包装的 interface 实例
        val cls = use<AudioClassifier>()
        scope.launch {
            val result = cls.classify(ClassifyRequest(samples))
            showAlert(result)
        }
    }
}
```

### 内部行为

```
onConnect()
  └─ 遍历 requiredInterfaces
       └─ client.resolveEndpoint(interfaceId, minVersion, maxVersion, ...)
       └─ 缓存 endpointId + 生成动态代理实例
```

`use<T>()` 返回的实例通过 `java.lang.reflect.Proxy` 实现：截获挂起函数调用 → 序列化 payload → `client.call(endpointId, methodId, payload)` → 反序列化 response。不存在派发路径，不接收 dispatch。

## NervusService : Component（provider 侧）

对应 manifest 中 `type: service` 的组件。它提供（注册）Interface 实现，接收 nervud 转发来的 Dispatch。

### Kotlin API

```kotlin
abstract class NervusService(config: ComponentConfig = ComponentConfig()) : Component(config) {

    /** 声明本 Service 提供的 Interface 实现 */
    protected abstract val providedInterfaces: List<ProvidedInterface>

    /**
     * 以挂起方式等待下一次 Dispatch 到达并返回结果。
     * ServiceStub 内部使用，实现业务接口的方法时调用。
     */
    protected fun dispatch(methodId: Int, payload: ByteArray, context: CallerContext): DispatchResult
}

/** 一个被提供的 Interface 实现 */
data class ProvidedInterface(
    val id: String,
    val major: Int,
    val minor: Int = 0,
    val instance: Any,                     // 实现了该 Interface 的业务对象
    val resourceHandle: String = "",       // 为空时 nervud 隐式取 base.main
)
```

### 使用示例

```kotlin
class AudioClassifierService : NervusService() {
    override val providedInterfaces = listOf(
        ProvidedInterface("nervus.interface.audio.classifier", 1, classifierImpl)
    )

    private val classifierImpl = object : AudioClassifier {
        override suspend fun classify(request: ClassifyRequest): ClassifyResult {
            return doClassify(request.samples)
        }
        override fun onAlert(): Flow<AlertEvent> {
            return alertFlow
        }
    }

    override fun onReady() {
        logger.info("音频分类服务就绪")
    }
}
```

### 内部行为

```
onConnect()
  └─ 遍历 providedInterfaces
       └─ host.registerEndpoint(interfaceId, major, minor, schemaHash, resourceHandle)
       └─ 为每个 method 注册 DispatchHandler
            └─ handler.register(methodId) { payload, ctx ->
                 // 反射调用 instance 的对应方法
                 // 序列化 result → DispatchResult
               }
```

Dispatch 路由规则：收到 `Dispatch(routeId, endpointId, methodId, payload, caller)` → 查 endpoint → 查 method mapping → Invoke `instance.method(payload)` → 返回 `DispatchResult(routeId, outcome)`。

## 与 manifest 的映射

```json
{
  "package_id": "com.example.audio",
  "components": [
    {
      "id": "control_console",
      "type": "app",
      "entry": "lib/control_console.jar",
      "runtime": "jvm",
      "launch_mode": "manual",
      "interfaces": [
        "nervus.interface.audio.classifier",
        "nervus.interface.motion.base"
      ]
    },
    {
      "id": "audio_classifier",
      "type": "service",
      "entry": "lib/audio_classifier.jar",
      "runtime": "jvm",
      "launch_mode": "on-demand"
    }
  ]
}
```

- `type: app` → 继承 `NervusApp`，`requiredInterfaces` 对应 `component.interfaces`
- `type: service` → 继承 `NervusService`，`providedInterfaces` 对应自身实现的接口

manifest 中的 `entry` 指向一个可执行 JAR 文件路径（打包插件自动生成薄 JAR，其 `META-INF/MANIFEST.MF` 的 `Main-Class` 指向对应的组件类；`Class-Path` 指向业务 JAR）。开发者在构建 DSL 中填写 `mainClass`，不直接填写 `entry`。

## 新增模块结构

```
nervus-app-sdk/
├── docs/
├── src/main/kotlin/com/nervus/sdk/
│   ├── ipc/                    # 已有：NervusClient / NervusServiceHost（不对外暴露概念）
│   ├── component/
│   │   ├── Component.kt        # 基类
│   │   ├── NervusApp.kt        # App 组件
│   │   └── NervusService.kt    # Service 组件
│   ├── annotations/
│   │   ├── Interface.kt        # @Interface
│   │   ├── Method.kt           # @Method
│   │   └── Event.kt            # @Event
│   └── runtime/
│       ├── InterfaceProxy.kt   # JVM 动态代理（consumer 侧 stub 生成）
│       └── ServiceStub.kt      # Dispatch 路由到方法（provider 侧）
```

IPC 层的 `NervusClient`/`NervusServiceHost` 标记为 `internal`，组件基类层是 SDK 的公共 API 表面。

## 不做的事

1. **不暴露 IPC 概念**：`request_id`、`route_id`、`endpoint_id`、`Dispatch`、`Frame`、`Envelope` 不在组件基类层的公共 API 中出现。
2. **不自己管理 manifest**：manifest 是.nspkg 安装包的一部分，由 pkgmanagerd + nervud pkgregistry 管理。SDK 不读不写 manifest 文件。
3. **不暴露跨进程调用**：`call()` / `dispatch()` 的底层由基类封装，组件开发者看不到它。
